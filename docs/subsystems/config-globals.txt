1.  How the parser works [verified]

   A flat if / else-if chain over argv, using two comparators:

   +--------------+-----------------------------------------------------------------+---------------+
   | Comparator   | Semantics                                                       | Used for      |
   +==============+=================================================================+===============+
   | __strcmpi    | exact, case-insensitive. == 0 means match                       | boolean flags |
   +--------------+-----------------------------------------------------------------+---------------+
   | FUN_0045acd0 | substring search; returns ptr into arg, else NULL. 0 = no match | numeric flags |
   +--------------+-----------------------------------------------------------------+---------------+

   FUN_0045acd0 uppercases heap copies of both strings and runs strstr,
   so it is stristr returning an offset pointer. The numeric flags then
   read their value with _atoi(match + N), where N is the length of the
   flag name. Every numeric flag in the binary is self-consistent under
   that rule (12/12), which is what pins each global to its flag - the
   else branches unwind in reverse chain order and sit far from their
   guards, so this offset identity is the reliable link, not proximity.

   Suggested name: Str_CaseInsensitiveFind / stristr_offset.

   NOTE:
      The comparator is a substring match, not a prefix match. -NoD3D
      contains -D3D only as a non-prefix substring, so chain ordering
      is what saves it here. That is fragile by construction and worth
      remembering when reasoning about flag precedence.

2.  Confirmed bug in the original [verified]

   -MinTextureHeight<n> writes to the max-texture-width global.

   The four texture-bound globals are laid out 0x004dc158/15c/160/164 =
   min-W / max-W / min-H / max-H. The parser writes:

   +-------------------+----------------+-----------------+
   | Flag              | Writes         | Should write    |
   +===================+================+=================+
   | -MinTextureWidth  | 0x004dc158     | 0x004dc158 [ok] |
   +-------------------+----------------+-----------------+
   | -MaxTextureWidth  | 0x004dc15c     | 0x004dc15c [ok] |
   +-------------------+----------------+-----------------+
   | -MinTextureHeight | 0x004dc15c [X] | 0x004dc160      |
   +-------------------+----------------+-----------------+
   | -MaxTextureHeight | 0x004dc164     | 0x004dc164 [ok] |
   +-------------------+----------------+-----------------+

   Evidence - cross-references:

   o 0x004dc15c has two writes from the parser (0x0041460a, 0x00414632).
   o 0x004dc160 has no writer at all: its only reference is a READ at
     0x00476397 inside the consumer FUN_00476100.
   o FUN_00476100 seeds defaults into 0x004dc15c and 0x004dc164 (the two
     maxima) at 0x004762b6 / 0x004762bb, and reads all four.

   So passing -MinTextureHeight silently clamps maximum texture width
   instead, and minimum texture height is permanently whatever
   FUN_00476100 leaves at 0x004dc160. A classic copy-paste slip.
   Preserve the behaviour in transcription; fix it only in a later,
   deliberate change.

3.  Undocumented flags [verified]

   Present in the binary, absent from the built-in help text:

   -BMG, -DataV2, -Modem, -waitForBlit<n>, -windowSystem,
   -TotalVideoMem<n>, -TextureVideoMem<n>, -saverecord, -savpath, -path,
   -noMMX (lowercase variant).

   -BMG at 0x004dc4ac sets ONE global, g_useBmgBranding at
   0x004dc1c4 (0x00414865).  It is the PUBLISHER BRANDING
   SWITCH - eight resource ids, GRAND PRIX against CHAMPIONSHIP
   - and the command line is only its third and last writer;
   see menu-resources.txt 5.4.1 for the default and the
   registry value that precede it.

   0x004dc1a4 IS A DIFFERENT FLAG.  It is set by the token
   compared immediately after -BMG, at 0x00414888, against a
   string built on the stack rather than a literal - so it has
   no name in a strings dump.  Input_OnKeyDown then uses it as
   a COUNTER, cycling it 1 -> 2 -> 1 alongside 0x004dc124,
   which is a debug or cheat gate rather than a branding one.
   [open] which flag spells it, and what the key does.

5.  Group B  -  0x004e4f44-0x004e4f98 (surface / texture)

   +-----------------------+------------+---------------------------------------+
   | Flag                  | Global     | Set to                                |
   +=======================+============+=======================================+
   | -NoDuplicateSurfaces  | 0x004e4f44 | 0                                     |
   +-----------------------+------------+---------------------------------------+
   | -OpaqueBlackLevel<n>  | 0x004e4f48 | atoi(+0x11); out of [1..3] -> 3, or 0 |
   +-----------------------+------------+---------------------------------------+
   | -CorrectRatioTextures | 0x004e4f94 | 1                                     |
   +-----------------------+------------+---------------------------------------+
   | (unidentified)        | 0x004e4f98 | 1                                     |
   +-----------------------+------------+---------------------------------------+

   What -OpaqueBlackLevel actually does, traced later [verified]: pure
   black is the transparent colour key for hardware textures, so a
   genuinely black texel would vanish. During texture upload every
   palette entry whose three channels all fall below

       (g_cfgOpaqueBlackLevel + 1) << (8 - bits)

   is raised to that floor. A higher setting pushes near-black colours
   further from the key, which is safer against black artwork
   disappearing and washes out dark artwork more. See
   subsystems/d3d-textures.txt section 3.

9.  Other findings

   o Registry root [verified]: SOFTWARE\DelphineSoft\MotoRacer..., read
     via FUN_0045a330(key, value, dest) for DataPath, SavingPath,
     Language. Confirms Delphine Software; matches the Dsed source-path
     prefix.
   o DirectX version gate [verified]: FUN_0045adb0 returns a version; if
     < 0x300 the game shows "The game require DirectX 3 or la..." and
     calls ExitProcess(1). Consistent with the DX3-era execute-buffer
     D3D path.
   o MMX default comes from FUN_00458fb0() - the CPU detection routine.
     -noCpuDetect zeroes 0x004e8cd0 and forces DAT_004dbcf0 = 0.

9.1.  A default is not findable by searching for writers

   Thirteen of these flags are spelled as a negation - -NoGouraud,
   -NoDither, -NoMMX, -NoAGP, -NoPal and the rest.  For every one of
   them the DEFAULT LIVES IN .data AS AN INITIALISED VALUE, and the
   only instruction that writes the global is the handler that turns
   the feature OFF.

   So the obvious method gets each one backwards: search for writers,
   find exactly one, see it store 0, and conclude the feature ships
   disabled.  It ships ENABLED.  0x004dc1d8 reads 01 00 00 00 in
   .data [verified]; the single writer is the -NoGouraud handler.

   READ .data FIRST, and treat a flag named as a negation as saying
   so in its own name - the positive is the default, or the switch
   would have nothing to disable.  The flag block at 0x004dc664
   confirms it in words: "Disable gouraud shading".

10.  Open questions

   o RESOLVED. 0x004dc1f4 is g_protectionPassed. It is set to 1
     unconditionally ONLY because this MOTO.EXE is cracked - the
     conditional jump guarding it at 0x00414331 was overwritten with 90
     90. In the original it is set only when the registry PId check
     passes, and when it is 0 Carac_Load subtracts 1.0 from every bike's
     NbSpeed. See subsystems/copy-protection.txt [verified].
