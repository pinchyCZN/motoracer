MotoRacer PC Reverse Engineering                           Analysis Note


                    SOURCE MAP FROM THE ASSERT SITES


Abstract

   Thirteen original source paths under D:\Dsed\mr320\ survive in the
   binary, and code-map.txt uses them to attribute functions to
   translation units. Each path is referenced from one or more assert
   sites, and every site pushes a LINE NUMBER beside it.

   That turns thirteen file names into forty-three anchors of the form
   file + line + function. The line numbers ORDER the functions within a
   file, which is worth more for the reconstruction than the attribution
   alone: a translation unit can be laid out in something close to its
   original sequence instead of by address.

   Everything here is [verified] - read out of the binary by
   tools/ghidra_assert_map.java, which re-derives the table from the
   reference set rather than from this document.

2.  What it establishes

   o Five consecutive lines, 163 to 167, are all TGA validation checks
     inside Bitmap_LoadFile. That is a run of guard clauses at the head
     of the loader, and it dates the file layout: the checks precede the
     two allocation failures at 172 and 177.

   o pageMainMenu.cpp reaches at least line 7629, and menu.cpp at least
     1666. The menu system is by some margin the largest translation
     unit the asserts expose.

   o Cdd_GetCaps carries the message Cdd::getCaps(), which names the
     original method outright and confirms both the Cdd class prefix and
     our chosen name for it.

   o Dsi_d3d.cpp:2474 and screen3d\dd.cpp:3648 share the message
     'impossible de locker la surface.' - the same failure written once
     for the D3D texture path and once for the DirectDraw surface path,
     which supports reading them as parallel implementations of one
     operation.

   o Four functions still named FUN_ are attributed to a file and a line
     by this table alone: FUN_00422280 in frame3d.cpp, FUN_0048b370 in
     animDecor.cpp, FUN_00479260 and FUN_00479630 in menu\menuTools.cpp,
     and FUN_00401e40 in screen3d\bankw.Cpp.

   o FUN_00462c60 contains asserts at player.cpp:3457 and :3764, so one
     function spans at least 307 source lines.

3.  Limits

   Forty-three sites is a thin sample of a game this size, and the files
   are the ones that happened to assert. Absence from this table says
   nothing: screen3d.cpp appears once, at line 1302, and is certainly
   thousands of lines long.

   The line numbers are also only as good as the assert placement. They
   locate the assert, not the start of the function, so they bound a
   function's position rather than fixing it. Two asserts in one
   function bound its extent from both ends, which is why the player.cpp
   pair is worth more than a single site.
